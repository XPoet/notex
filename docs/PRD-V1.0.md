# MemoBox（墨盒）产品需求文档

> 版本：V1.0  
> 产品形态：PC 桌面应用  
> 当前目标平台：macOS
> 中文名称：墨盒  
> 英文名称：MemoBox

---

## 1. 产品概述

### 1.1 产品背景

用户在日常工作和生活中，经常需要快速保存临时文本、代码片段、账号说明、操作记录、网页摘录、截图和剪贴板图片。传统云笔记通常功能较重，依赖账号和网络，且用户需要承担隐私、同步和服务稳定性风险；普通文本文件又缺乏分类、标签、搜索、图片管理和批量导出能力。

MemoBox 是一款纯本地、轻量级、无需联网的 PC 端个人笔记管理与信息速记应用。产品以“打开即记、粘贴即存、自动保存、随时可导出”为核心体验，帮助用户在本地集中管理零散信息，并确保数据完全由用户掌控。

### 1.2 产品定位

MemoBox 不是多人协作知识库，也不是复杂的在线文档平台，而是一款强调以下能力的个人桌面工具：

- 快速记录：减少新建、命名和手动保存操作。
- 本地优先：笔记、图片、索引和配置全部保存在本机。
- 结构化管理：通过最多 5 级分类和多标签组织信息。
- 快速查找：通过全局搜索找到包含关键信息的笔记。
- 数据可迁移：支持将笔记导出为通用 Markdown 文件。
- 轻量稳定：启动快、无需联网，优先保证记录和检索效率。

### 1.3 产品目标

1. 用户能够在数秒内创建并记录一条笔记。
2. 用户粘贴文本时，系统仅写入纯文本，不保留富文本样式。
3. 用户粘贴图片时，系统按原图片格式保存，不进行格式转换。
4. 用户无需手动点击保存，编辑内容可自动保存。
5. 用户能够通过分类、标签和全局搜索快速找到历史笔记。
6. 用户能够将单条笔记、分类或标签下的笔记导出为 Markdown 文件。
7. 软件在完全离线环境下可正常使用全部核心功能。

### 1.4 非目标

V1.0 暂不包含：

- 用户注册、登录和账号体系。
- 云同步、多端同步和在线存储。
- 数据备份和备份恢复功能。
- 用户修改或迁移数据目录。
- 在线 AI、OCR、语音转写和网页抓取。
- 富文本编辑器和所见即所得编辑。
- 从剪贴板直接新建笔记。
- 图片格式转换和统一压缩。
- 笔记历史版本管理。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 开发者：保存代码片段、命令、接口说明、错误处理记录。
- 办公人员：记录会议要点、临时任务、业务资料和操作步骤。
- 内容创作者：收集灵感、标题、素材、段落和截图。
- 注重隐私的个人用户：保存不希望上传至云端的信息。
- 重度剪贴板用户：频繁复制文本和图片，需要长期整理和检索。

### 2.2 核心使用场景

1. 用户创建一条笔记，粘贴从网页或聊天工具复制的文本，系统仅保留纯文本内容。
2. 用户在笔记中粘贴 PNG、JPEG、WebP 或 GIF 图片，系统按可识别的原始格式保存到本地。
3. 用户通过最多 5 级分类管理项目、工作、学习和生活资料。
4. 同一条笔记同时关联“重要”“待处理”“紧急”等多个标签。
5. 用户忘记某段信息存在哪条笔记中，通过关键字搜索并找到对应笔记。
6. 用户将某一分类或标签下的笔记批量导出，迁移至其他 Markdown 工具。

## 3. 产品设计原则

### 3.1 本地优先

- 所有业务数据保存在固定的本地应用数据目录。
- 核心功能不得依赖网络、远程字体、CDN 或在线接口。
- 默认不上传笔记、图片、搜索词、使用记录和设备信息。
- V1.0 不允许用户修改数据目录，避免迁移过程中出现数据遗漏或损坏。

### 3.2 自动而透明

- 编辑内容自动保存，用户无需手动点击保存。
- 编辑区明确显示“正在编辑”“保存中”“已保存”“保存失败”等状态。
- 图片写入和批量导出过程应显示进度和结果。

### 3.3 防误操作

- 普通删除优先进入回收站，不直接永久删除。
- 删除分类时必须明确对子分类和笔记的处理方式。
- 永久删除和清空回收站前必须二次确认。

### 3.4 数据可迁移

- 笔记正文使用纯 Markdown 源码格式保存。
- 图片以本地文件形式存储，并通过相对路径与笔记关联。
- 图片导出时保持原有格式，不进行统一转换。
- 导出结果可被常见 Markdown 编辑器读取。

## 4. 产品范围与优先级

### 4.1 V1.0 必须实现（P0）

- 笔记的增、删、改、查。
- 最多 5 级的树状分类管理。
- 标签的增、删、改、查。
- 一条笔记关联多个标签。
- 按分类和标签筛选笔记。
- 在编辑器中粘贴纯文本。
- 在编辑器中粘贴图片，并按原格式本地保存。
- 纯 Markdown 源码编辑。
- 输入停顿约 1 秒后自动保存。
- 编辑器撤销和重做。
- 全局搜索并返回包含关键字的笔记。
- 单条笔记、分类和标签维度的 Markdown 导出。
- 回收站、恢复笔记和永久删除。
- 当前版本仅支持 macOS。

### 4.2 建议实现（P1）

- 笔记置顶。
- 最近编辑列表。
- 常用键盘快捷键。
- 浅色、深色和跟随系统主题。
- 笔记排序方式设置。
- 分类节点悬浮时显示加号，点击后在该分类下新建笔记。

### 4.3 后续版本（P2）

- Markdown 文件批量导入。
- 笔记历史版本。
- 全局快捷键呼出快速记录窗口。
- 数据备份和备份恢复。
- 自定义数据目录。
- 更多附件类型。
- Markdown 预览或分栏预览。
- 自定义编辑器主题和字体。

## 5. 信息架构与界面结构

### 5.1 主界面

建议采用三栏桌面布局：

1. **左侧导航栏**
   - 全部笔记
   - 最近编辑
   - 分类树
   - 标签入口
   - 回收站
   - 设置

2. **中间笔记列表**
   - 当前分类、标签或搜索条件
   - 新建笔记按钮
   - 搜索与筛选入口
   - 笔记标题与正文摘要
   - 排序和置顶状态

3. **右侧编辑区**
   - 笔记标题
   - 分类与标签在标题下同一行展示，通过更多操作修改
   - Markdown 源码编辑器
   - 保存状态
   - 导出、删除和更多操作

### 5.2 辅助窗口或弹窗

- 分类管理弹窗。
- 标签管理弹窗。
- 导出配置弹窗。
- 设置页面。
- 图片保存失败、格式不支持、磁盘空间不足等异常提示。

## 6. 核心数据模型

### 6.1 笔记 Note

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| title | 笔记标题 |
| content | Markdown 兼容的纯文本正文 |
| category_id | 所属分类，可为空 |
| is_pinned | 是否置顶 |
| is_deleted | 是否进入回收站 |
| created_at | 创建时间 |
| updated_at | 最后修改时间 |
| deleted_at | 删除时间，可为空 |

规则：

- 一条笔记只能直属一个分类，也可以不属于任何分类。
- 一条笔记可关联多个标签。
- 标题允许重复。
- 标题为空时，系统优先取正文第一行的前若干字符作为标题；仍为空则显示“无标题笔记”。
- 新建空白笔记但未输入任何内容时，退出后可自动清理，避免产生大量无意义空笔记。

### 6.2 分类 Category

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| name | 分类名称 |
| parent_id | 父分类 ID，根分类为空 |
| level | 分类层级，取值为 1 至 5 |
| sort_order | 同级排序值 |
| created_at | 创建时间 |
| updated_at | 修改时间 |

业务规则：

- 分类最多支持 5 级嵌套。
- 根分类为第 1 级，第 5 级分类下不得再创建子分类。
- 同一父分类下不允许出现完全相同的分类名称。
- 移动分类时不得将分类移动到自身或自身的后代节点中。
- 移动后的分类及全部后代分类不得超过 5 级。
- 分类树支持展开、收起和拖拽排序。

### 6.3 标签 Tag

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| name | 标签名称 |
| created_at | 创建时间 |
| updated_at | 修改时间 |

规则：

- 标签名称全局唯一，前后空格自动去除。
- 删除标签只解除标签与笔记的关联，不删除笔记。
- 标签重命名为已存在名称时，提示用户是否合并标签。

### 6.4 图片资源 Asset

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| note_id | 所属笔记 |
| file_name | 本地文件名 |
| original_name | 原始文件名，可为空 |
| extension | 原图片扩展名 |
| relative_path | 相对资源目录路径 |
| mime_type | 原图片 MIME 类型 |
| size | 文件大小 |
| width / height | 图片尺寸 |
| hash | 文件内容哈希，用于去重和校验 |
| created_at | 创建时间 |

业务规则：

- 图片保持可识别的原始编码格式，不主动转换为其他格式。
- 文件扩展名应与实际图片格式一致。
- 图片文件使用 UUID 或内容哈希命名，避免重名。
- 删除笔记进入回收站时，图片文件暂不删除。
- 笔记永久删除后，仅删除不再被任何笔记引用的图片。
- 支持的图片格式至少包括 PNG、JPEG、WebP 和 GIF。
- 对系统可读取但未明确支持的格式，应在保存前进行校验。

## 7. 功能需求

## 7.1 笔记管理

### 7.1.1 新建笔记

- 用户可在全部笔记、某一分类或某一标签页面新建笔记。
- 从分类下新建时，默认归属当前分类。
- 从标签筛选结果中创建时，默认关联当前标签。
- 新建后自动聚焦标题或正文编辑区。
- 新建操作必须由用户主动触发，不提供“从剪贴板新建笔记”入口。

### 7.1.2 编辑笔记

- 支持修改标题、正文、所属分类和标签。
- 正文编辑器采用纯 Markdown 源码模式。
- V1.0 不提供富文本编辑和所见即所得编辑。
- V1.0 暂不要求提供 Markdown 实时预览。
- 用户切换笔记、切换分类、关闭窗口或退出应用前，应立即执行一次保存。
- 编辑器支持文本选择、复制、剪切、粘贴及常用快捷键。

### 7.1.3 删除笔记

- 默认删除操作将笔记移动至回收站。
- 回收站支持恢复到原分类；原分类已不存在时恢复到“未分类”。
- 回收站支持单条永久删除和清空回收站。
- 永久删除前必须二次确认，并说明操作不可恢复。
- V1.0 默认不自动清空回收站，避免用户因长期未打开软件而丢失数据。

### 7.1.4 笔记列表

- 展示标题、正文摘要和置顶状态；标签在右侧编辑区的分类旁展示。
- 默认按“置顶优先、最后修改时间倒序”排列。
- 支持按创建时间、修改时间和标题排序。
- 列表应支持长文本截断和空状态提示。

### 7.1.5 查看与定位

- 点击笔记后在编辑区打开。
- 从搜索结果打开笔记后，应保留搜索条件，便于返回继续查看。
- V1.0 不要求在笔记正文中定位或高亮具体命中位置。

## 7.2 分类管理

### 7.2.1 创建分类

- 可在根节点或第 1 至第 4 级分类下创建子分类。
- 第 5 级分类下隐藏或禁用“新建子分类”入口。
- 分类名称不能为空，并自动去除首尾空格。
- 同级分类重名时禁止创建并提示原因。

### 7.2.2 编辑与移动分类

- 支持重命名。
- 支持拖拽调整同级顺序。
- 支持拖拽或通过菜单修改父分类。
- 移动时校验循环嵌套。
- 移动后任一分类层级超过 5 级时，禁止移动并提示原因。

### 7.2.3 删除分类

删除分类时提供两种方式：

1. **仅删除当前分类**：当前分类中的直属笔记和子分类移动到父级。
2. **删除整个分类分支**：当前分类、全部子分类及其笔记一起进入回收站。

补充规则：

- 删除根级分类并选择“仅删除当前分类”时，其直属笔记和子分类移动到根级。
- 删除确认框显示受影响的子分类数量和笔记数量。
- 删除整个分类分支时，分类和笔记应保留必要关联，以支持笔记从回收站恢复。

### 7.2.4 分类统计

- 分类节点默认显示当前分类及全部后代分类的笔记总数。
- 进入某分类后，默认展示当前分类及其子分类中的全部笔记。
- “仅查看当前分类直属笔记”可作为 P1 筛选能力。

## 7.3 标签系统

### 7.3.1 标签管理

- 支持创建、重命名、删除和搜索标签。
- 支持在编辑笔记时快速创建新标签。
- 支持为一条笔记添加多个标签。
- 重复添加同一标签时不产生重复关系。

### 7.3.2 标签筛选

- 点击标签后展示所有关联笔记。
- 支持多标签筛选。
- 多标签筛选默认采用“同时包含全部选中标签”的 AND 逻辑。
- 可提供切换为“包含任一标签”的 OR 逻辑作为后续增强。
- 标签删除后，笔记内容和分类关系保持不变。

## 7.4 剪贴板粘贴

### 7.4.1 粘贴纯文本

- 用户只能在已打开的笔记编辑器中执行粘贴。
- 剪贴板同时包含 HTML、富文本和纯文本时，仅读取纯文本内容。
- 不保留字体、字号、颜色、背景色和其他富文本样式。
- 尽量保留换行、缩进、制表符和基础文本结构。
- 粘贴内容插入当前光标位置。
- 粘贴完成后触发自动保存。

### 7.4.2 粘贴图片

处理流程：

1. 用户在 Markdown 编辑器中执行粘贴。
2. 系统识别剪贴板中的图片数据。
3. 校验图片格式、文件大小和可读取性。
4. 按可识别的原始图片格式写入本地资源目录。
5. 创建图片资源记录。
6. 在当前光标位置插入 Markdown 图片引用。
7. 触发自动保存。

示例：

```md
![图片](./assets/{asset-id}.png)
```

### 7.4.3 图片处理规则

- 图片不进行主动格式转换。
- PNG 保存为 PNG，JPEG 保存为 JPEG/JPG，WebP 保存为 WebP，GIF 保存为 GIF。
- GIF 在可获得原始 GIF 数据时应保留动图内容。
- 默认不主动调整图片尺寸。
- 默认不主动压缩图片质量。
- 文件扩展名应根据图片真实格式确定，不能仅依赖剪贴板提供的名称。
- 图片保存失败时，不得插入无效 Markdown 引用。
- 磁盘空间不足或数据目录不可写时，应停止保存并提示原因。
- 当剪贴板仅提供系统位图、无法取得原始编码格式时，系统使用 PNG 作为无损兜底格式；该情况属于操作系统和来源应用的剪贴板限制。

## 7.5 自动保存

### 7.5.1 触发规则

- 用户停止输入 1 秒后触发保存。
- 连续输入期间采用防抖机制，避免每次按键都写入磁盘。
- 以下操作发生前立即保存：切换笔记、关闭窗口、退出应用、删除当前笔记、导出当前笔记。
- 分类和标签关系发生变化后立即保存。

### 7.5.2 保存状态

编辑区显示以下状态：

- 正在编辑。
- 保存中。
- 已保存。
- 保存失败，请重试。

保存失败时：

- 当前编辑内容必须保留在内存或临时草稿中。
- 系统自动重试有限次数。
- 持续失败时提示可能原因，例如磁盘空间不足、数据目录无权限或数据库损坏。
- 用户关闭应用前，应再次提示存在未保存内容。

### 7.5.3 数据写入安全

- 数据库写入使用事务。
- 图片文件写入成功后，再写入资源记录和笔记引用关系。
- 图片写入失败时，不修改笔记正文。
- 应用异常退出后，已经完成自动保存的内容不得丢失。
- V1.0 不提供独立的备份恢复或历史版本恢复界面。

## 7.6 撤销与重做

- 支持编辑器内的撤销和重做。
- macOS：`Command + Z` 撤销，`Command + Shift + Z` 重做。
- 撤销范围包括标题和正文的当前编辑会话。
- 切换到其他笔记后，可以清空当前笔记的撤销栈。
- V1.0 的撤销能力不等同于跨会话历史版本；应用重启后无需保留完整撤销记录。

## 7.7 全局搜索

### 7.7.1 搜索目标

全局搜索的目标是：根据用户输入的关键字，找到包含相关信息的笔记。

V1.0 不要求：

- 高亮搜索关键字。
- 自动定位正文中的具体命中位置。
- 展示正文中的全部匹配片段。
- 搜索图片中的文字。
- 提供 OCR。

### 7.7.2 搜索范围

默认搜索：

- 笔记标题。
- 笔记正文。
- 分类名称。
- 标签名称。

其中，正文是最主要的搜索范围。

### 7.7.3 搜索交互

- 用户可从主界面进入全局搜索。
- 输入关键字后延迟约 200 至 300 毫秒执行搜索。
- 搜索结果以笔记列表形式展示。
- 每条结果显示标题、简短摘要、所属分类、标签和更新时间。
- 全局搜索结果的标题、正文摘要、分类和标签中的匹配关键字均高亮显示。
- 点击搜索结果后打开对应笔记。
- 列表内筛选及从全局搜索打开笔记时，在中间笔记卡片的标题、正文摘要和右侧编辑器正文中高亮匹配的关键字；多个以空格分隔的关键字分别高亮，不区分英文大小写。
- 高亮仅改变显示，不写入笔记内容或撤销历史；清空列表搜索或离开搜索上下文后取消高亮。
- 清空搜索条件后返回全部笔记或此前浏览位置。

### 7.7.4 搜索规则

- 默认不区分英文字母大小写。
- 支持中文、英文、数字和常见符号。
- 多个以空格分隔的关键字默认采用 AND 匹配。
- 回收站中的笔记默认不参与搜索。
- 搜索结果默认按相关度排序；相关度相同时按最后修改时间倒序排列。

## 7.8 Markdown 导出

### 7.8.1 导出范围

- 导出当前单条笔记。
- 导出指定分类下的笔记。
- 工作台导出弹窗提供“当前笔记”和“当前分类”；选择“当前分类”导出当前笔记所属分类的全部直属笔记（包含“未分类”，不含子分类和回收站笔记）。
- 导出指定分类及其全部子分类下的笔记。
- 导出指定标签下的笔记。

### 7.8.2 单条笔记导出结构

```text
导出目录/
├── 笔记标题.md
└── assets/
    ├── image-1.png
    └── image-2.jpg
```

Markdown 中使用相对路径：

```md
![图片](./assets/image-1.png)
```

### 7.8.3 分类批量导出结构

分类批量导出时：

- 在导出根目录保留分类目录结构。
- 所有图片统一存放在导出根目录的 `assets` 文件夹中。
- 所有 Markdown 文件中的图片引用均指向根目录 `assets`。
- 同一图片在同一次导出任务中只复制一次。
- 根据 Markdown 文件所在目录深度，自动生成正确的相对路径。

示例：

```text
导出目录/
├── 工作/
│   ├── 项目 A/
│   │   └── 接口说明.md
│   └── 周报.md
├── 学习/
│   └── Vue 笔记.md
└── assets/
    ├── 3f6a8c.png
    ├── 92ab11.jpg
    └── e7d301.gif
```

`工作/项目 A/接口说明.md` 中的图片引用示例：

```md
![图片](../../assets/3f6a8c.png)
```

### 7.8.4 标签批量导出结构

- 标签导出到以标签名命名的文件夹。
- 每条笔记导出为独立 Markdown 文件。
- 所有图片统一存放在导出根目录的 `assets` 文件夹中。
- 同一笔记在单次导出任务中只导出一次。
- 不按照原分类重复创建多份笔记文件。

### 7.8.5 图片导出规则

- 导出时保持图片原格式，不进行转换。
- 导出的扩展名与实际图片格式一致。
- 图片文件名使用稳定的资源 ID 或哈希值，避免重名。
- Markdown 中的内部图片路径必须替换为导出后的正确相对路径。
- 同一资源被多条笔记引用时，导出目录中只保留一份文件。

### 7.8.6 文件命名与冲突

- 自动移除当前操作系统不允许的文件名字符。
- 空标题使用“无标题笔记-{短 ID}”。
- 同名文件自动追加 `-2`、`-3` 等序号。
- 图片文件名不依赖笔记标题，避免笔记重命名后资源路径变化。

### 7.8.7 导出结果

- 显示导出进度、成功数量和失败数量。
- 显示最终导出目录。
- 部分笔记导出失败时，不回滚已经成功的文件。
- 导出完成后提供“打开文件夹”操作。

## 7.9 本地数据目录

### 7.9.1 数据目录规则

V1.0 使用固定的系统应用数据目录，不允许用户修改。

macOS 建议路径：

```text
~/Library/Application Support/MemoBox/
```

### 7.9.2 目录结构

```text
MemoBox/
├── database/
│   └── memobox.db
├── assets/
│   └── {note-id}/
│       ├── {asset-id}.png
│       ├── {asset-id}.jpg
│       └── {asset-id}.gif
├── temp/
├── logs/
└── config/
```

### 7.9.3 数据目录要求

- 数据库、图片资源、日志和配置分目录存放。
- 设置页显示当前数据目录。
- 提供“打开数据目录”操作。
- 不提供“修改数据目录”“迁移数据目录”或“选择存储位置”功能。
- 数据目录不可写时，应阻止继续编辑并显示明确错误。
- 日志不得记录完整笔记正文、图片内容和敏感剪贴板信息。

## 7.10 设置

V1.0 设置项包括：

- 查看当前数据目录。
- 打开数据目录。
- 默认导出目录。
- 笔记默认排序方式。

- 应用版本。

V1.0 不提供：

## 8. 关键业务流程

### 8.1 新建并自动保存笔记

1. 用户点击“新建笔记”。
2. 系统创建空白笔记并打开编辑区。
3. 用户输入标题或 Markdown 正文。
4. 用户停止输入约 1 秒。
5. 系统保存笔记并更新搜索索引。
6. 界面显示“已保存”。

### 8.2 粘贴纯文本

1. 用户在 Markdown 编辑器中执行粘贴。
2. 系统读取剪贴板纯文本。
3. 系统忽略 HTML 和富文本样式。
4. 纯文本插入当前光标位置。
5. 系统触发自动保存。

### 8.3 粘贴图片

1. 用户在 Markdown 编辑器中执行粘贴。
2. 系统读取剪贴板图片数据。
3. 系统识别可获得的图片编码格式。
4. 图片按原格式写入本地资源目录；无法取得原格式时使用 PNG 无损保存。
5. 系统创建图片资源记录。
6. Markdown 正文插入相对路径引用。
7. 系统触发自动保存。

### 8.4 删除分类分支

1. 用户选择删除分类。
2. 系统统计子分类和笔记数量。
3. 用户选择“仅删除当前分类”或“删除整个分支”。
4. 系统展示影响范围并二次确认。
5. 执行移动或进入回收站操作。
6. 刷新分类树、笔记列表和搜索索引。

### 8.5 批量导出分类

1. 用户在分类菜单中选择“导出”。
2. 选择是否包含子分类和目标目录。
3. 系统校验目标目录写入权限。
4. 系统创建分类目录和根级 `assets` 目录。
5. 系统写出 Markdown 文件。
6. 系统复制原格式图片并重写相对路径。
7. 系统显示导出结果。

## 9. 异常与边界处理

### 9.1 存储异常

- 数据目录无权限：阻止继续编辑并显示处理建议。
- 磁盘空间不足：停止图片保存和数据库写入。
- 数据库写入失败：保留当前编辑内容并提示重试。
- 数据库被占用：有限次数重试，失败后提示用户。
- 数据库异常：停止继续写入，避免扩大数据损坏。

### 9.2 图片异常

- 剪贴板内容不是可识别图片：不执行图片保存。
- 图片格式不支持：提示“暂不支持该图片格式”。
- 图片文件过大：显示文件大小，并允许用户取消粘贴。
- 图片写入失败：不插入 Markdown 引用。
- 图片文件丢失：保留原 Markdown 引用，并显示资源缺失提示。
- 图片 MIME 类型与扩展名不一致：以检测到的真实格式为准。
- 无法获取原始编码格式：使用 PNG 无损兜底保存。

### 9.3 导出异常

- 目标目录不可写：导出前阻止操作。
- 文件名冲突：自动追加序号。
- 图片资源缺失：Markdown 继续导出，并在结果中列出缺失资源。
- 用户中途取消：停止后续文件写入，保留已完成内容并提示导出不完整。
- 相对路径生成失败：该笔记标记为导出失败，不写入错误引用。

### 9.4 分类边界

- 第 5 级分类下不得创建子分类。
- 禁止循环嵌套。
- 移动分类后超过 5 级时禁止移动。
- 批量移动分类时，应同时校验其全部后代节点层级。
- 大量分类节点时采用按需渲染或虚拟列表，避免分类树卡顿。

## 10. 非功能需求

### 10.1 性能

在普通办公电脑和约 10,000 条文本笔记规模下，目标为：

- macOS 冷启动进入主界面不超过约 2 秒。
- 普通列表切换响应不超过约 200 毫秒。
- 常见关键字搜索结果在约 300 毫秒内返回。
- 输入过程无明显卡顿，自动保存不得阻塞编辑线程。
- 图片写入在后台执行，并显示处理中状态。

### 10.2 稳定性

- 所有数据库写入使用事务。
- 图片文件和数据库记录避免出现半写入状态。
- 已完成自动保存的内容在应用异常退出后不得丢失。
- 删除图片前必须确认不存在其他笔记引用。
- 搜索索引异常时，可以重新构建索引，不影响原始笔记数据。

### 10.3 隐私与安全

- 不要求账号登录。
- 不主动发起网络请求。
- 不收集笔记内容、剪贴板内容、搜索词和使用行为。
- 剪贴板仅在用户执行粘贴或主动触发剪贴板笔记时读取。
- 日志不得记录完整笔记正文和敏感剪贴板内容。

### 10.4 兼容性

- 首发平台为 macOS。
- 当前 V1.0 仅构建、验收和分发 macOS 产物。
- 快捷键、文件名规则、路径分隔符和系统菜单以 macOS 为准。
- 导出的 Markdown 和图片目录应尽量跨平台可用。

### 10.5 可用性

- 所有核心功能均可通过鼠标完成。
- 常用功能提供键盘快捷键。
- 删除、恢复、保存失败等状态应使用明确文案，避免只依赖颜色表达。
- 空状态应提供下一步操作入口。

### 12.1 核心功能验收

- 用户可以创建最多 5 级分类。

- 分类批量导出后，所有图片位于导出根目录的 `assets` 文件夹。
- 多层目录中的 Markdown 图片相对路径正确。
- 断开网络后，所有核心功能均可正常运行。
- macOS 能完成核心业务流程。
- 设置中不能修改数据目录。
- 产品中不存在备份和备份恢复入口。

- 删除标签不会删除笔记。
- 删除分类时严格按照用户选择处理笔记和子分类。
- 永久删除笔记后，不再使用的图片可以被安全清理。
- 每个本地图片引用都能映射到资源记录和实际文件。
- 图片扩展名和实际编码格式保持一致。
- 同一图片在单次批量导出中只复制一次。
- 导出过程中单条失败不影响其他笔记成功导出。

- 日常新建一条文本笔记所需核心操作不超过 2 次点击。
- 自动保存测试中无可复现的数据丢失。

- 在剪贴板能够提供原始编码的情况下，图片粘贴前后格式保持一致。
- 分类批量导出的 Markdown 和图片可被常见编辑器正确打开。

## 14. 风险与技术边界

### 14.1 需要技术验证的风险

- 某些来源应用复制图片时，剪贴板只提供系统位图数据，不提供原始图片文件或原始编码格式。
- GIF 从不同应用复制时，可能无法获得完整动图数据。
- 大尺寸图片原样保存会增加磁盘占用和写入压力。
- 自动保存频率与数据库写入性能之间需要平衡。
- 中文全文搜索的索引体积和匹配准确性需要验证。
- Electron、Tauri 等桌面框架对剪贴板和本地文件能力的支持存在差异。

### 14.2“保持原图片格式”的产品边界

1. 剪贴板提供原始图片文件或明确编码格式时，按该格式保存。
2. 剪贴板仅提供系统位图数据时，系统无法还原复制前的原始编码格式。
3. 此类情况使用 PNG 作为无损兜底格式。
4. 文件扩展名必须依据实际写入格式生成，不能伪装为来源格式。
5. 该限制应在产品和技术文档中说明，但普通粘贴流程无需反复打扰用户。
